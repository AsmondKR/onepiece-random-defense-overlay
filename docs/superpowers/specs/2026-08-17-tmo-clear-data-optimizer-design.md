# TMO 클리어 데이터 실시간 빌드 최적화 설계

날짜: 2026-08-17
상태: 승인(자율 진행 선호), 구현 진행

## 목표

티모지지 공개 클리어 기록(신 이상 난이도)을 수집·집계해 추천 우선순위를 데이터 기반으로
실시간 최적화하고, 신 이상에서 마지막 스토리(에그헤드) 클리어 후 나오는 그린블러드의
사용처를 추천한다.

## 근거 데이터

- API: `GET https://tmo.gg/_api/ranks/ordr2/clears?limit=50&next=<nextCursor>`
  - 응답: `{ clears: [...], nextCursor: string|null }`, limit 최대 50
  - 레코드: `id`, `user`, `createdAt`(ISO), `difficulty`(신/악몽/지옥),
    `unitCount`, `units[{code,count,name,grade}]`
- 신 이상 = `신` + `악몽`(변질). `지옥`은 제외한다.
- 사용자 지시: **unitCount가 적을수록 잘 짠 빌드** → 품질 가중치.
- 그린블러드: 신 이상에서 에그헤드(마지막 스토리) 클리어 보상. 전설/히든 유닛에
  주기적 범위 스턴·고정 대미지·공속 증가 부여. 가이드 43747 기록:
  왜곡 유닛(코알라 V30h, 퀸 IC0h, 페로나 840h, 에이스 V50h)과
  쿠마(030h) "그린블러드 주면 스턴 사라짐".

## 구성 요소

### 1. 수집 도구 — `tools/UpdateTmoClearSamples.ps1`

- 커서 페이지네이션으로 최근 기록 수집, 기본 `-SinceDays 14`, `-MaxRecords 40000` 캡.
- 산출: `Data/tmo-clear-samples.json`
  ```json
  {
    "schemaVersion": 1,
    "source": "https://tmo.gg/_api/ranks/ordr2/clears",
    "capturedAt": "...",
    "samples": [
      { "i": "id", "t": "createdAt", "d": "신", "n": 11,
        "u": [ { "c": "Q30h", "k": 1 } ] }
    ]
  }
  ```
- 난이도는 전부 저장하고 필터링은 앱 집계에서 수행한다(재수집 없이 정책 변경 가능).

### 2. 런타임 증분 갱신 — `TmoClearRefreshService`

- 앱 시작 시 백그라운드 1회: 로드된 표본의 최신 `createdAt` 이후 신규 기록만
  최대 30페이지 fetch, `%LOCALAPPDATA%\OrandOverlay\tmo-clear-cache.json`에 병합(id 중복 제거).
- 실패 시 조용히 번들+캐시 데이터만 사용(fail-closed). 원격 데이터가 손상 JSON이면 캐시를 갱신하지 않는다.
- `AppSettings.ClearDataAutoRefresh`(기본 true)로 비활성화 가능.
- HTTP GET 전용, 쓰기 없음.

### 3. 집계 — `ClearBuildStats`

- 입력: 번들 표본 + 사용자 캐시(중복 id 제거, 캐시 우선).
- 필터: `difficulty ∈ {신, 악몽}`.
- 가중치 `w = wq × wr`
  - 품질 `wq = clamp(medianUnitCount / unitCount, 0.5, 2.0)` — 표본 중앙값 대비.
  - 최신성 `wr = 0.5^(ageDays / 14)`, 기준 시각은 데이터셋 최신 기록(시계 비의존).
- 목표별 통계: 등급이 `초월/불멸/영원/제한`으로 시작하는 유닛 rawcode를 목표로 보고,
  해당 목표가 포함된 클리어의 나머지 유닛을 공출현 집계.
  - `Share(goal, code) = Σw(포함 클리어) / Σw(목표 클리어)` (0..1)
  - `SampleCount(goal)` = 목표 포함 클리어 수(비가중).
- 전역 통계: 신+ 전체 유닛 채용률(표본 부족 목표 안내용).

### 4. 엔진 통합 — `RecommendationEngine`

- 생성자에 선택적 `ClearBuildStats` 주입(기존 호출부 하위 호환).
- `CommunityPriorityScore`: 목표 `SampleCount ≥ 12`이면 `round(Share × 100)`,
  미만이면 기존 수작업 테이블(야마토/우솝/조로/징베) 폴백.
- `IsCommunityCore`(조로 홀딩 축 F50h/O30h 특례)는 데이터로 대체하지 않고 유지한다.
  채용률 상위와 "홀딩 축"은 다른 개념이라 실측 top-3로 바꾸면 홀더 탐색이 깨질 수 있다.
  (구현 중 확정한 결정 — Share 기반 코어 판정은 도입하지 않음)
- 역할 코어(풀이감 102 → 스턴 1.4 → 풀방깎 211) 우선 구조는 변경하지 않는다.
  클리어 점수는 같은 역할 버킷 내 순서만 바꾼다.
- 지원 추천에 근거 문자열 노출: "신+ 클리어 N판 · 채용률 X퍼센트".

### 5. 그린블러드 어드바이저 — `GreenBloodAdvisor`

- 트리거: 미사용 그린블러드 보유(item_greenblood > 0; 자동 인식 A13A 또는 수동 보정).
  그린블러드는 신+ 에그헤드 클리어 후에만 존재하므로 난이도 게이트가 자동 충족된다.
- 순위 규칙:
  1. 현재 추천에 왜곡 유닛(V30h/IC0h/840h/V50h)이 있으면 "왜곡 제작에 예약" 최우선.
  2. 아니면 현재 패의 전설/히든 중 신+ 클리어 채용률(현재 목표 기준) 상위에 적용 권고.
  3. 쿠마(030h)는 스턴 코어(1.4) 미완성 시 경고와 함께 후순위.
- 이완코브 히든 홀더 조건(그린블러드+모비딕) 기존 규칙 유지.
- 출력: `GreenBloodAdvice(대상 유닛, 사유, 경고)` 목록, 오버레이 표시는 클릭 통과
  꺼짐 상태의 추천 상세에 한 줄 추가.

## 오류 처리

- 표본 파일 없음/손상: 클리어 통계 비활성 → 수작업 테이블 폴백, 설정 화면에 상태 표시.
- 캐시 손상: 캐시 무시하고 번들만 사용, 다음 갱신에서 재작성.
- 원격 스키마 변화(필수 키 누락): 해당 레코드 건너뜀, 전체 실패 아님.

## 테스트 (SmokeTests)

1. 품질 가중치: unitCount 적은 클리어의 지원 유닛이 더 높은 share.
2. 최신성 감쇠: 오래된 클리어보다 최신 클리어 가중.
3. 난이도 필터: 지옥 클리어는 집계 제외.
4. 표본 임계값: 11판 이하 목표는 수작업 테이블 폴백, 12판 이상은 클리어 점수 사용.
5. 엔진 순서: 역할 코어 우선 유지 + 같은 버킷 내 클리어 점수 순.
6. 그린블러드: 왜곡 예약 우선, 쿠마 경고, 미보유 시 어드바이스 없음.
7. 캐시 병합: id 중복 제거, 손상 캐시 무시.
8. 기존 113개 테스트 무손상.

## 제외 범위

- 난이도 자동 감지(메모리) — 그린블러드 감지가 게이트를 대신한다.
- 클리어 기록의 그린블러드 적용 대상 역추적(API에 없음).
- 지옥 이하 난이도 통계.
