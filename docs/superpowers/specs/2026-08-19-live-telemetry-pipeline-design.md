# 라이브 플레이 데이터 파이프라인 설계

작성일 2026-08-19. 목적: 오버레이 사용자의 클리어/실패 결과를 자체 수집해
추천 로직을 게이트 있는 자동 튜닝으로 보완한다. 티모지지 클리어 데이터가
커버하지 못하는 신호 — "추천을 따랐을 때 실제로 이겼는가", "실패 판에는
무엇이 편중되는가" — 를 확보하는 것이 핵심이다.

## 결정 사항 (인터뷰 확정)

- 승패 라벨은 **하이브리드**: 지금 읽을 수 있는 것은 즉시 수집하되 라벨은
  `unknown`으로 보내고, 승패 판정 메모리 프로브가 완성되면 `clear/fail`
  확정 라벨을 붙인다. 스키마는 처음부터 라벨 유무를 구분한다.
- 수집 범위는 **내 슬롯 데이터만**. 닉네임·계정·IP·채팅·타인 패는 수집하지
  않는다. 설치 시 1회 생성하는 익명 UUID로 판수만 구분한다.
- 자동화 수준은 **게이트 있는 자동 튜닝**: 집계는 제안 리포트를 만들고,
  통계 기준을 넘는 항목만 스냅샷 가중치로 자동 반영한다. 역할 로직과
  수작업 테이블은 자동화 대상이 아니다.
- 인프라는 **Cloudflare 무료 티어**(Worker + D1, workers.dev 주소).
- 집계는 **개발 PC**(기존 클리어 수집 스케줄 작업)에서 돌린다. Worker는
  수집·저장만 하는 우체통이다. 유저 앱에 새 서버 의존을 만들지 않는다
  (업로드 1회뿐, 통계 수신은 기존 GitHub raw 갱신 경로).
- 유저 피드백은 파이프라인 밖: 사용자가 직접 전달하면 리포트와 대조해
  수작업 테이블을 조정한다.

## 전체 흐름

```
오버레이(세션 종료 감지) ──POST /v1/records──> Cloudflare Worker ──> D1
                                                      │
개발 PC 수집기(하루 2회) <── GET /v1/records?since (API 키) ──┘
  → work/telemetry/ 원본 적재(비공개)
  → 집계 + 게이트 판정
  → Data/orand-live-stats.json 갱신 + work/telemetry/reports/ 제안 리포트
  → 커밋/푸시 → 유저 앱은 기존 데이터 갱신 경로로 수신
```

## 클라이언트 (오버레이)

`MatchTelemetryRecorder` 신설.

- **기록 시점**: 세션 경계 확정(`ConfirmsSessionBoundary`) 또는 앱 종료 시
  진행 중이던 판. 판당 레코드 1개(~2KB).
- **레코드 스키마 v1**:
  - `schemaVersion`, `recordId`(UUID), `anonId`(설치 UUID), `capturedAt`
  - `appVersion`, `mapVersion`, `warcraftVersion`
  - `settings`: 오로성, 항법, 목표 유닛, 빌드 방향
  - `finalHand`: rawcode+수량 목록(내 슬롯), `completedTops`: 완성 상위 목록
  - `progress`: 세션 시작/종료 시각, 마지막 관측 유닛 수
  - `recommendation`: 마지막 1순위 추천 유닛, 추천 상위 5 스냅샷
    (준수율 계산은 집계 시점에 수행 — 클라는 원자료만 보냄)
  - `outcome`: `unknown | clear | fail` + `outcomeSource`: `none | memoryProbe`
- **업로드**: fail-silent. 실패하면 `%LOCALAPPDATA%\OrandOverlay\telemetry\pending\`
  큐에 보관(최대 50판 또는 30일)하고 다음 실행 때 재시도. 게임 성능에
  영향을 주지 않도록 업로드는 백그라운드 스레드, 타임아웃 짧게(5초).
- **옵트아웃**: 설정에 "익명 플레이 통계 보내기" 체크박스(기본 켬).
  끄면 생성·전송 모두 0건. 패치노트에 수집 항목을 고지한다.

## Worker (Cloudflare)

역할은 우체통. 로직을 넣지 않는다.

- `POST /v1/records`: JSON 스키마 검증(필수 필드·타입), 크기 상한 4KB,
  `schemaVersion` 확인. 익명ID+IP 기준 레이트리밋(분당 6, 일 200 —
  판당 1개면 과분). 통과 시 D1 `records`에 적재.
  - 테이블: `records(id TEXT PK, anon_id TEXT, received_at INTEGER,
    app_version TEXT, map_version TEXT, outcome TEXT, payload TEXT)`
- `GET /v1/records?since=<rowid>&limit=<n>`: 수집기 전용. `Authorization`
  헤더의 API 키(Worker secret)와 대조. 유저 앱은 이 경로를 알지 못한다.
- 응답은 최소화: 성공 204, 검증 실패 400, 레이트리밋 429, 저장 실패 507.
- 배포: wrangler, 무료 티어. 저장량 추정: 1만 판 ≈ 20MB (D1 한도 5GB).

## 집계 + 게이트 자동 튜닝 (개발 PC)

기존 클리어 수집 스케줄 작업(하루 2회)에 단계 추가.

- **pull**: 마지막 커서 이후 레코드를 받아 `work/telemetry/records-YYYY-MM.jsonl`
  에 원본 보관(저장소 밖, 비공개).
- **집계 산출물**:
  1. `Data/orand-live-stats.json` (배포됨): 목표별 실사용 판수, 추천 준수율
     분포, 클리어율(확정 라벨만), 실패 편중 유닛 목록, 표본 수, 생성 시각.
  2. 제안 리포트 `work/telemetry/reports/YYYY-MM-DD-proposals.md` (비공개):
     게이트 기준을 넘은 항목과 근거 수치.
- **게이트 기준** (모두 충족해야 자동 반영):
  - 표본 ≥ 30판 (라벨 확정분 기준)
  - 효과의 95% 신뢰구간이 0을 벗어남 (이항 비율 차이)
  - 반영 폭 상한: 우선도 가중 ±10% 이내 (급격한 추천 변화 방지)
- 게이트 통과분은 스냅샷의 `weights` 필드로 자동 반영하고 커밋 메시지에
  항목·수치를 명시한다. 롤백은 커밋 단위.

## 앱 로직 반영 (v1 최소)

- 추천 근거 라벨에 "실사용 n판 · 클리어율 x%" 표기 추가 (표본 있을 때만).
- `orand-live-stats.json`의 게이트 통과 가중치만 우선도에 반영.
  역할 로직·수작업 테이블·티모지지 학습 경로는 그대로 둔다.

## 에러 처리

- Worker 다운/네트워크 실패: 클라이언트는 조용히 큐에 보관. 사용자에게
  아무것도 표시하지 않는다(통계는 부가 기능).
- 수집기 pull 실패: 다음 주기에 커서부터 재시도. 원본은 D1에 남아 있음.
- 스키마 불일치(구버전 클라): Worker가 400으로 거절, 클라는 3회 실패 시
  해당 레코드 폐기(무한 재시도 방지).
- 집계 산출 실패: 스냅샷 갱신을 건너뛰고 로그만 남김 — 잘못된 통계 배포
  방지(fail-closed).

## 테스트

- 스모크(기존 스위트): 레코드 생성·직렬화, 옵트아웃 시 0건, 큐 보관·재시도
  ·폐기 정책, 준수율 계산, 게이트 판정 경계값.
- Worker: wrangler 로컬 환경에서 검증·레이트리밋·적재·pull 왕복 테스트.
- 통합: 로컬 Worker에 실제 레코드 업로드 → 수집기 pull → 집계 → 스냅샷
  생성까지 1회 왕복.

## 마일스톤

- **M1**: Worker 배포 + 클라 업로드(라벨 unknown) + 옵트아웃. 데이터 축적 시작.
- **M2**: 수집기 확장 + 집계 + `orand-live-stats.json` 배포(표기만, 튜닝 없음).
- **M3**: 승패 판정 메모리 프로브(라이브 세션 필요) → `outcomeSource=memoryProbe`
  확정 라벨 시작.
- **M4**: 확정 라벨 표본이 게이트 기준을 넘기 시작하면 자동 튜닝 활성.

## 비목표

- 타인 슬롯 데이터 수집, 채팅·계정 정보 수집.
- 티모지지 서버 접속(기존 합의 유지 — 클라이언트는 tmo.gg에 접속하지 않는다).
- 역할 로직·수작업 테이블의 자동 변경.
- 실시간 서버 통계 조회(앱은 스냅샷 배포 경로만 사용).
