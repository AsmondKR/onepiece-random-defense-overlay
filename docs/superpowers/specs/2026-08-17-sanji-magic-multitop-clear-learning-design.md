# 상디초월 + 긴급소집: 마딜 클리어 학습 설계

날짜: 2026-08-17 · 상태: 구현 완료(스모크 156/156, publish 반영) · 대상: OrandOverlay

## 배경과 문제

사용자는 상디초월(H90H, `초월 [마딜]`) + 긴급소집(연합세력, 다상위 항법)으로 플레이하며,
클리어 기록 기반 학습이 이 조합에 맞게 동작하기를 원한다. "마딜이라 물딜이랑은 또 달라."

실측(번들 신+ 스냅샷 27,489판 중 상디초월 92판 — 멀티탑 90 / 1상위 2):

| 역할 | 상디초월 실측(중앙값) | 물딜 기준 |
|---|---|---|
| 이감 | 145 (자체 발동이감 50 포함) | 102 |
| 스턴 | 1.4 | 1.4 |
| 방깎 | **0** | 211 |
| 마방깎 | 1 (p75=18, 에넬 경유) | — |
| 보잡/광잡 | 각 1 | 상위별 |

확인된 결함:

1. **마딜 오판**: `StrategyProfileFor`가 `바제스=가능`으로 물딜을 판정하는데 상디초월도
   바제스 가능이라 **방깎 211 물딜 파이프라인**이 적용된다. 실측 방깎 중앙값은 0.
2. **항법 조건화 부재**: 클리어 API에 항법 필드가 없어 1상위(구조: 상위 1기)만 전용
   프로필이 있고, 긴급소집 같은 다상위 항법은 1상위 클리어가 섞인 전체 프로필을 쓴다.
3. **마딜 역할 미집계**: `마법방어력 감소`가 StrategyMetrics에 없어 후보 선별에서 무시된다.
4. **카탈로그 공백**: 상디 멀티탑 채용 상위인 S-베어(1A0h, 세라핌 22%)와 센고쿠 불멸
   (MB0h, 마딜 17%)이 카탈로그·라이브 assets.json 어디에도 없다.

## 설계

### A. ClearBuildStats: TopScope 3단 프로필

- `enum TopScope { Any, SoloTop, MultiTop }` 도입. 프로필 맵을 전체/1상위(상위 1기)/
  다상위(상위 ≥2기) 세 벌로 집계한다. 다상위는 긴급소집 등 다상위 항법의 구조적 대리
  변수다(API에 항법 필드가 없으므로 상위 기수로 조건화).
- `GoalProfile/PriorityScore/IsCore/Evidence`의 `bool soloTopOnly` → `TopScope scope`.
  스코프 표본 <12판이면 전체 프로필로 후퇴(기존 규칙 유지).
- `GoalClearProfile.SoloTop`(bool) → `Scope`. `ClearEvidence`도 `Scope`를 담고
  `SoloTop`은 계산 프로퍼티로 유지(기존 패턴 매칭 호환).

### B. RecommendationEngine: 마딜 전략 파이프라인

- 마딜 판정: 티어 문자열 `[마딜]` 포함(카탈로그 공식 표기). `바제스` 물딜 판정보다
  먼저 분기한다.
- 마딜 GoalStrategyProfile (실측 근거):
  - SlowTarget 102 유지(자체 이감 포함 집계), StunTarget 1.4 유지
  - **ArmorReductionTarget 0** (방깎 스텝 제거)
  - **MagicArmorReductionTarget 1** (신규 — 마방깎 소스 최소 1점, 중앙값 근거)
  - BossControlTarget 1, BerserkBossControlTarget 1 (중앙값 각 1)
  - FillCommunitySupports true (공속·마뎀증 같은 수치화 어려운 버퍼는 채용률 순)
- `StrategyMetrics`에 `MagicArmorReduction`("마법방어력 감소") 추가, 파이프라인에
  방깎 스텝과 대칭인 마방깎 스텝 추가. 공중이동 스텝의 "방깎 겸용 우선"은 마딜에서
  "마방깎 겸용 우선"으로 일반화.
- 항법→스코프: `AllowsMultipleTopUnits` → MultiTop, 1상위(바헌/로얄로더) → SoloTop,
  계엄령(상위 조합 불가) → Any. `_singleTopNavigation` bool을 `_topScope`로 대체.

### C. UI 근거 라벨

`신+ 1상위 n판` 외에 다상위 스코프면 `신+ 다상위 n판`으로 표기(MainWindow·Overlay).

### D. 카탈로그 등록

세라핌 전례(수기 등록) 그대로 S-베어(1A0h)·센고쿠 불멸 [마딜](MB0h)을
`tmo-unit-catalog.json`에 추가. 레시피 미공개라 조합 후보로는 뜨지 않고(의도),
티어 통계·향후 데이터 대비 목적. 이미지 URL은 라이브 클리어 API에서 확보.

### 대안 검토

- 마방깎을 물딜 방깎처럼 큰 수치 목표로: 기각 — 실측상 보편 스택이 아니고(중앙값 1)
  에넬 제한 채용(30%)에 좌우되므로 하드 타깃은 에넬 강요가 된다. 채용률 정렬이 처리.
- 클리어 상세 API에서 항법 추출: 기각 — 목록·상세 어디에도 항법 필드 없음(실측).
- 상디 전용 수작업 우선도 테이블: 기각 — 92판 실측 채용률이 이미 있고(≥12), 목표는
  "클리어 기록으로 학습"이므로 실측 우선 + 기존 폴백 구조 유지.

## 후속 보정 (2026-08-17, 유저 실전 피드백)

- **목박 필러 보정**: 비비 변화(W50h)는 빌드 완성 후 남는 패로 넣는 마무리 필러라
  클리어 동시출현이 우선순위를 과대평가한다(야마토+바헌 실측 51%). 빌드 크기
  (꽉 짠 빌드에서도 54%)·목표 특이도(lift 2.4) 어느 구조 신호로도 걸러지지 않아,
  도메인 지식 기반 `LeftoverFillerRawcodes`로 실측 점수를 무시하고 수작업 테이블로
  후퇴시킨다. 보정 후 야마토+바헌: 사보 > 에이스 > 센고쿠 > 드래곤 > 킹.
- **고인물 검증**: 상디초월+긴급소집 추천이 실전 검증됨(토키·갓에넬·코알라·네코마
  ㅇㅈ, 4~5순위는 패 따라 유동 — 정상). "선택은 실시간 패, 화면 순서는 채용률"
  구조 유지.

## 후속 2: 취향 조건부 학습 (2026-08-17)

같은 상위라도 행보가 취향으로 갈린다(에제+마젠 편안러 vs 단일·끝딜 도전러 — 고인물
검증, 클러스터 분리 실측). `ResolveProfile`이 보유 지원급 유닛을 앵커로 삼아 "그
유닛과 같이 쓰인 클리어"만 재집계한다:

- 앵커 인정: 목표 클리어 채용률 0 < x < 50%(범용 제외), 목박 필러 제외, 목표 자신 제외
- 특이도(낮은 채용률)순 그리디 교집합, 표본 12판 미만으로 쪼개지는 앵커는 건너뜀
- 재집계는 기존 품질(중앙값/판 크기)·최신성(반감기 14일) 가중 그대로
- 근거 라벨: "신+ 다상위 · 에넬 동반 27판 중 채용률 n%"
- 적용 범위: 마딜 목표 우선(사용자 지시 "일단 상디초로"), 물딜 확대는 검증 후
- 실측: 에넬 보유 시 아오키지 41% > 코알라 31% > 토키 24%로 재정렬(마젠 계열 부상)

## 테스트

- TopScope: 다상위 프로필이 1상위 전용 지원을 제외하는지, 표본 부족 시 전체 후퇴,
  Evidence 스코프 라벨. 기존 soloTopOnly 호출부 갱신.
- 마딜 파이프라인: 상디초월 + 긴급소집에서 (1) 방깎 전용 유닛 미선택, (2) 마방깎 소스
  ≥1 확보, (3) 스턴 1.4 세트 유지, (4) 보잡·광잡 확보.
- 번들 실데이터: H90H 다상위 프로필 표본 ≥50, 긴급소집 추천 근거가 다상위 스코프.
- 기존 회귀 포함 전체 156/156 통과(PASS 라벨도 실측 개수로 정정).
